## Відповіді на контрольні питання

### 1. Порівняйте та назвіть переваги та недоліки таких методів сортування: сортування бульбашкою, сортування вибором, сортування вставкою.

* **Сортування бульбашкою (Bubble sort):**
    * *Принцип роботи:* Багаторазово проходить по масиву, порівнюючи сусідні елементи та міняючи їх місцями, якщо вони стоять у неправильному порядку.
    * *Переваги:* Максимальна простота реалізації; стабільність; легко оптимізується за допомогою прапорця обмінів для вже відсортованих даних.
    * *Недоліки:* Дуже повільний на великих масивах через велику кількість операцій обміну (запису в пам'ять).

* **Сортування вибором (Selection sort):**
    * *Принцип роботи:* На кожному кроці знаходить мінімальний (або максимальний) елемент у невідсортованій частині та міняє його місцями з першим елементом цієї частини.
    * *Переваги:* Робить мінімальну можливу кількість операцій обміну — не більше $O(n)$ (корисно, коли запис у пам'ять коштує дорого).
    * *Недоліки:* Завжди виконує однакову кількість порівнянь $O(n^2)$ навіть на повністю відсортованому масиві; у класичній реалізації є нестабільним.

* **Сортування вставкою (Insertion sort):**
    * *Принцип роботи:* Послідовно бере елементи з невідсортованої частини і вставляє кожен на правильну позицію у вже відсортовану ліву частину масиву.
    * *Переваги:* Найшвидший серед простих квадратичних алгоритмів на малих або майже відсортованих масивах; стабільний; працює як «online-алгоритм» (може сортувати дані в міру їх надходження).
    * *Недоліки:* Повільний на великих невідсортованих масивах через необхідність зсувати багато елементів вправо.

### 2. Оцініть кожен з методів відповідно до критеріїв (час роботи, додаткова пам'ять, стабільність) та назвіть додаткові критерії.

| Критерій | Bubble sort (бульбашкою) | Selection sort (вибором) | Insertion sort (вставкою) |
| :--- | :--- | :--- | :--- |
| **Час роботи (найкращий)** | $O(n)$ *(з прапорцем обмінів)* | $O(n^2)$ | $O(n)$ |
| **Час роботи (середній)** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| **Час роботи (найгірший)** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| **Додаткова пам'ять** | $O(1)$ *(in-place)* | $O(1)$ *(in-place)* | $O(1)$ *(in-place)* |
| **Стабільність** | Так (стабільний) | Ні (нестабільний) | Так (стабільний) |

**Інші критерії, за якими можна порівнювати алгоритми сортування:**
1. **Адаптивність:** здатність алгоритму прискорюватися на частково відсортованих даних (`Insertion sort` та оптимізований `Bubble sort` — адаптивні; `Selection sort` — ні).
2. **Кількість операцій запису/обміну:** критично для флеш-пам'яті чи великих об'єктів (тут лідирує `Selection sort` із $O(n)$ обмінами).
3. **Онлайновість (Online):** здатність сортувати потік даних без необхідності мати весь масив у пам'яті одразу (`Insertion sort`).
4. **Локальність посилань (кеш-дружність):** наскільки ефективно алгоритм використовує кеш процесора при послідовному доступі до пам'яті.

### 3. Який випадок є найкращим або найгіршим для роботи цих алгоритмів? Який з методів забезпечить у цих випадках найкращий/найгірший результат?

* **Найкращий випадок (масив уже відсортований у потрібному порядку):**
    * **Найкращий результат** покажуть **Insertion sort** та оптимізований **Bubble sort** — вони виконають лише один лінійний прохід за час **$O(n)$** (зроблять $n-1$ порівнянь і $0$ обмінів).
    * **Найгірший результат** у цьому випадку покаже **Selection sort**, оскільки він не вміє визначати, що масив уже відсортований, і все одно виконає квадратичну кількість порівнянь — **$O(n^2)$**.

* **Найгірший випадок (масив відсортований у зворотному порядку):**
    * Усі три алгоритми працюватимуть за квадратичний час **$O(n^2)$**.
    * Проте на практиці **найгірший (найповільніший) результат** покаже **Bubble sort**, оскільки він виконує максимальну кількість дорогих операцій обміну елементів (по 3 присвоювання на кожен обмін на кожній ітерації).
    * **Insertion sort** також зробить максимальну кількість зсувів ($O(n^2)$), але кожен зсув — це лише одне присвоювання замість повноцінного обміну через третю змінну.
    * **Selection sort** виконає $O(n^2)$ порівнянь, але зробить найменше операцій запису в пам'ять — лише $O(n)$ обмінів.

### 4. Що означають позначення $O(1)$, $O(n)$, $O(n^2)$?

Це **нотація «О-велике» (Big-O notation)**, яка описує асимптотичну складність алгоритму — тобто те, як швидко зростає час виконання або обсяг використаної пам'яті зі збільшенням кількості вхідних даних $n$:

* **$O(1)$ — константна складність:** час виконання або витрати пам'яті не залежать від розміру масиву $n$ (наприклад, звернення до елемента масиву за індексом або виділення кількох локальних змінних для сортування на місці).
* **$O(n)$ — лінійна складність:** час виконання зростає прямо пропорційно кількості елементів $n$. Якщо збільшити масив у 10 разів, алгоритм працюватиме приблизно в 10 разів довше (наприклад, один прохід по масиву).
* **$O(n^2)$ — квадратична складність:** час виконання зростає пропорційно квадрату кількості елементів $n$ (характерно для алгоритмів із двома вкладеними циклами). Якщо збільшити масив у 10 разів, час роботи зросте у $10^2 = 100$ разів.
